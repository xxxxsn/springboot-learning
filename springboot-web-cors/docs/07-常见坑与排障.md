# 常见坑与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 前端仍报 CORS，curl 却是 200 | 响应没有 `Access-Control-Allow-Origin`，或源站写错 | 看响应头，不要只看业务 `code` |
| `allowedOrigins("*")` 加上 `allowCredentials(true)` | 凭证场景不能回显 `*` | 列出具体源，或改用 `allowedOriginPatterns`。Framework 6.2 在 `validateAllowCredentials()` 才抛，setter 不报错 |
| 配了全局 CORS，某个接口却把商城也放行了 | `@CrossOrigin` 与全局源站取并集 | 要收紧就不要在方法上再加源 |
| 前端读不到自定义响应头 | 缺少 `exposedHeaders` | 把需要读的头写进 `exposedHeaders` |
| 未配置路径的 OPTIONS 是 403 `Invalid CORS request` | Spring 把带预检头的 OPTIONS 交给预检处理器，没有 CORS 配置就拒绝 | 给该路径加映射，或让网关处理预检 |
| 网关和 MVC 都加了 CORS | 响应头重复，浏览器直接失败 | 只在一处配置 |
