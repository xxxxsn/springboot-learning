# 常见坑与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `@CurrentUser` 得到空对象而不是请求头里的用户 | 解析器排在 ModelAttribute 兜底之后，或参数没有注解 | 用 `addArgumentResolvers`，参数必须带 `@CurrentUser` |
| `@ApiResult` 完全没包装 | 用了 `addReturnValueHandlers`，`@RestController` 已被 `@ResponseBody` 处理器抢走 | 初始化后把自定义处理器插到列表首位 |
| 启动报适配器和 `WebMvcConfigurer` 循环依赖 | 同一个配置类既实现 `WebMvcConfigurer` 又注入 `RequestMappingHandlerAdapter` | 安装返回值处理器的类不要实现 `WebMvcConfigurer` |
| 响应变成 `R` 套 `R` | 包装前没判断返回值类型 | `instanceof R` 时原样写出 |
| 缺用户却是 500 | 解析器抛了非业务异常 | 抛 `BusinessException(UNAUTHORIZED)`，交给 common |
| 访客的 `id` 字段不见了 | `R` 和空字段的 `NON_NULL` | 见 #26；本模块访客只保证 `name` 和 `guest` |
