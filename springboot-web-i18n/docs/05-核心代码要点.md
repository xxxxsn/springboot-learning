# 核心代码要点

## 为什么 message 存 key

`I18nErrorCode.getMessage()` 返回 `auth.login.invalid_credentials` 这种字符串。`BusinessException` 沿用 common 的构造，全局处理把这段字符串放进 `R.message`。前端拿去翻译，后端不再维护中文提示。

数字码仍然留给程序分支（例如 41001 表示凭证错误），key 留给文案。两者都要稳定，不要把句子写进数字码的注释以外的返回值。

## 为什么校验要单独一个 Advice

`springboot-common` 的 `GlobalExceptionHandler` 会把第一条字段错误拼成「字段名 + 注解默认文案」。那是给还没做 i18n 的模块用的。本模块的 `I18nExceptionHandler` 使用 `@Order(HIGHEST_PRECEDENCE)`，只接管：

- `MethodArgumentNotValidException`
- `BindException`
- `HttpMessageNotReadableException`

这三种都返回 `common.param_invalid`。业务异常仍走 common，因为抛出时 message 已经是 key。

## 登录和文件只是场景壳

`I18nDemoService` 的口令是常量 `secret`，文件只看扩展名。真实登录会哈希比对，真实上传会看文件头。那些不属于本模块。

## MessageSource 对照

`GET /api/i18n/messages?key=` 读取 `LocaleContextHolder`，也就是容器根据 `Accept-Language` 设好的语言。`getMessage(key, null, key, locale)` 的第三个参数是默认值：资源里没有这个 key 时返回 key 本身，而不是 500。

分离前端不要调用这个接口来显示错误。它用来核对 properties 是否写对，以及给服务端渲染留下对照。
