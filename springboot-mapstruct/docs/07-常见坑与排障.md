# 常见坑与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `Unknown property "buyerName"`，实体明明有字段 | 写了 `annotationProcessorPaths` 后，Maven 不再自动发现 Lombok | 路径里同时放 lombok 和 `lombok-mapstruct-binding` |
| 改了 Mapper 注解，运行还是旧行为 | 实现类是编译生成的 | 重新 `mvn test` 或 IDE 打开注解处理。生成物在 `target/generated-sources/annotations` |
| 客户端传的 id 进了库 | 属性同名会自动映射 | 创建方法上 `@Mapping(target = "id", ignore = true)` |
| 改了个字段名，接口少了一截还没报错 | 默认 `unmappedTargetPolicy=IGNORE` | 本模块用 `ERROR`。源侧仍然 IGNORE，因为摘要本来就少字段 |
| 局部更新把备注改成了 null | 普通映射会把 null 写进去 | 只在 `@MappingTarget` 的方法上加 `NullValuePropertyMappingStrategy.IGNORE` |
| 没传 `items`，旧明细没了 | 更新已有 `List` 时生成的是 `clear()` + `addAll()`，不判断源是不是 null；`toItems(null)` 又是空列表 | `update` 里 `ignore` items，在 `@AfterMapping` 看到请求真带了列表再替换。`RETURN_DEFAULT` 只加在创建和出参上 |
| 改了拷贝的明细，原单也变了 | 同类型 `List` 只复制列表外壳 | 用 `@Named` 逐条 `copy` 元素 |
| 只改街道，省被清空 | 嵌套对象被整个 new 了一个 | 再提供 `updateAddress(..., @MappingTarget Address)`，已有地址会走更新 |
| `record` 上做局部更新编译失败 | record 没有 setter | 实体用可变类，VO 继续用 record |
| `expression = "java(address.getProvince())"` 空指针 | 这是拼进生成代码的字符串，没有空检查 | 用 `@Named` 方法，自己判空 |
| 1.999 元被收成 200 分 | 手写换算时用了 `double` 或默认舍入 | `BigDecimal`，超过两位小数直接抛业务异常 |
| 注入 `OrderMapper` 失败 | `componentModel` 还是默认的 | 设成 `spring`。`Mappers.getMapper` 不会进容器 |
| 详情时间是 `2026-11-24T08:30:00`，和文本字段不一致 | `createdAt` 是 LocalDateTime，JSON 归 Jackson | 文本用 MapStruct `dateFormat`。要改 JSON 去 #26 |
| IDE 能跑、命令行 Unknown property | IDE 用了 Lombok 插件，Maven 没配处理器 | 以 `mvn test` 为准 |

换算失败和未知状态码抛 `BusinessException`，由 common 的 `GlobalExceptionHandler` 收成 `R`，HTTP 仍是 200。
