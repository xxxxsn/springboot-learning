# 核心代码要点

## 为什么实体不用 record

`@MappingTarget` 要把请求里的非空字段写进已有对象，需要 setter。record 只有构造器，做不到「只改备注」。所以 `Order` / `Address` / `OrderItem` 是 Lombok 可变类，请求和 VO 才是 record。

## 创建

`toEntity` 忽略 `id`、`orderNo`、`createdAt`、`amountCent`。同名的 `id` 如果不 ignore，客户端传 `1` 就会进库。

`statusCode`（Integer）到 `status`（枚举）走 `@Named("toStatus")`。金额不在这个方法里填，等明细映射完，`@AfterMapping` 用「单价分 × 数量」汇总。这样请求里就算自己带了金额也作废。

服务端拿到实体后再赋主键、`ORD-{id}` 和 `createdAt`。主键从大于 `2^53` 的序列递增，VO 里的 `id` 由 MapStruct 按内置的 Long→String 转成字符串。

## 嵌套和集合

- `AddressRequest` → `Address`，同名自动映射
- `OrderItemRequest.priceYuan` → `OrderItem.priceCent`，用 `MoneyMapper`
- `List` 会找元素方法，不用手写 for
- 创建和详情的列表方法单独加了 `NullValueMappingStrategy.RETURN_DEFAULT`，没传明细时接口得到 `[]` 而不是 null
- 这个策略没有加在 `@Mapper` 上。加在全局的话，更新方法里的 null 列表也会变成空列表，把旧明细清掉

## 局部更新

`update` 使用 `NullValuePropertyMappingStrategy.IGNORE`：源字段为 null 时不调用 setter。这条规则只管普通属性。

集合是另一条生成路径：目标 `List` 已经有值时，实现类会 `clear()` 再 `addAll()`，**不会先判断源列表是不是 null**。创建用的 `toItems` 又把 null 收成空列表，于是「没传 items」会把旧明细清空。所以 `items` 在 `update` 上 `ignore`，改到 `@AfterMapping`：请求里的 `items` 非 null 才 `setItems(toItems(...))` 并重算金额。

地址另外有 `updateAddress`。目标上已经有地址时，MapStruct 选这个更新方法，所以只传 `street` 不会把省、市抹掉。目标上还没有地址时，走 `toAddress` 新建。

明细没有按 sku 合并，非 null 就是整表替换。

总览接口先 `copy` 再 `update`，预览不写回内存里的样例。地址的 `copy` 会 new 一个对象。同类型 `List` 不会自动逐条复制，只是 `new ArrayList<>(source)`，元素仍是原引用，所以明细列表用 `@Named("copyItems")` 自己循环。

## 出参

`toDetail` / `toSummary`：

- `amountCent` → `amountYuan`
- `status.code` / `status.label` → 数字码和中文
- `createdAt` 原样留 LocalDateTime，另外用 `dateFormat = "yyyy-MM-dd HH:mm:ss"` 得到 `createdAtText`
- `fullAddress` 用 `@Named`，不用 `expression = "java(...)"`。后者是字符串，编译器不检查空指针

`toSummaries` 是集合映射：有元素方法就会生成循环。

## 和 Spring 的关系

`componentModel = spring` 的实现类带 `@Component`。启动日志里的类名应包含 `OrderMapperImpl`。手写 `Mappers.getMapper` 拿不到容器里的 `MoneyMapper`。
