# 验证步骤

在仓库根目录：

```bash
mvn -B test -pl springboot-mapstruct -am
```

启动：

```bash
mvn -pl springboot-mapstruct -am spring-boot:run
```

然后打开 `api.http`。业务失败也是 HTTP 200，看 body 里的 `code`。这是 `springboot-common` 的约定。

| 请求 | 期望 |
|---|---|
| `GET /api/mapstruct/overview` | `sampleDetail.id` 为 `9007199254740993`；`amountYuan=39.80`；`createdAt` 含 `T`，`createdAtText` 为 `2026-11-24 08:30:00`；`afterPatchPreview` 只改了备注和状态 30，买家仍是张三 |
| 再 `GET /orders/sample` | 状态仍是 20，备注仍是 null（预览没有落库） |
| `POST /orders` 带 `"id": 1` 和两条明细 | 返回的 id 不是 `1`，以 `9007` 开头；金额 `40.80`；`fullAddress` 为拼接结果 |
| `POST` 不带 `items` | `items=[]`，`amountYuan=0` |
| `statusCode=99` | `code=400`，message 含「未知订单状态」 |
| `priceYuan=1.999` | `code=400`，message 含「两位小数」 |
| `PATCH` 只带备注和状态 | 买家、地址、金额不变 |
| `PATCH` 地址只带 `street` | 省、市保留 |
| `PATCH` 带新的 `items` | 明细被替换，金额重算 |
| `PATCH /orders/1` | `code=404` |

启动日志应有一行 `[mapstruct] ready mapper=...OrderMapperImpl port=8030`。创建和更新还有 `[mapstruct] create` / `patch`，只打单号、状态和金额分，不打地址。
